## Authentication and security findings

- [`resolveAuth`](https://github.com/bcharleson/linkedincli/blob/88f775ef95c5b8ad1d3b6d1056f94ef92282b8bb/src/core/auth.ts) prioritizes explicit Chrome import over flags, environment, and the CLI config. A normal command with `--from-chrome` reads the chosen local Chrome profile at invocation; it does not call `login` or save credentials to the CLI config.
- [`chrome-cookies.ts`](https://github.com/bcharleson/linkedincli/blob/88f775ef95c5b8ad1d3b6d1056f94ef92282b8bb/src/core/chrome-cookies.ts) copies Chrome's cookie database and WAL/SHM files into a temporary directory, queries LinkedIn-domain cookies with `sqlite3`, removes the copied database in a `finally` block, and on macOS calls Keychain for `Chrome Safe Storage` to decrypt them. A Keychain prompt may appear; the copy exists briefly on disk. The code needs `li_at` and `JSESSIONID` and constructs a full LinkedIn cookie header. Chrome profile and encryption compatibility are unverified. The default profile is `Default`; this need not be the profile the owner uses.
- Avoid `linkedin login`: [`login.ts`](https://github.com/bcharleson/linkedincli/blob/88f775ef95c5b8ad1d3b6d1056f94ef92282b8bb/src/commands/auth/login.ts) writes session cookies to `~/.linkedin-cli/config.json` **before** validating them, even with `--from-chrome`. Do not pass cookies in CLI arguments or chat.
- The default Node HTTP transport can cause LinkedIn to invalidate the session, according to the project's README. The optional `curl-impersonate` transport is not installed here (`curl_chrome123` was not found). Its [implementation](https://github.com/bcharleson/linkedincli/blob/88f775ef95c5b8ad1d3b6d1056f94ef92282b8bb/src/core/transport.ts) passes HTTP headers, including cookies and CSRF token, as subprocess arguments; local process inspection may expose them while the child runs. Do not use it as-is without accepting or addressing that credential-exposure trade-off. Browser fingerprint matching does not guarantee safety.
- The client retries certain errors up to three times. One CLI invocation therefore does **not** guarantee exactly one HTTP request. An authenticated query could still mark messages read or trigger a LinkedIn challenge, session invalidation, or account restriction. The user's LinkedIn session is valuable; no live trial is implied by this preparation.

A single successful test is account- and version-specific, not a guarantee of future behavior. Compare DM, InMail and invitation coverage separately when samples are available.
