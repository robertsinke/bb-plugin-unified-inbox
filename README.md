# Unified Inbox (work in progress)

Rail page for personal and business Gmail and WhatsAgent, opened from an inbox icon on the sidebar rail (the same place as Agent Calendar). The thread stays on the left and the message list on the right. The rail icon shows the unread count. The thread name in the chat header switches which conversation stays beside the inbox, and remembers the last choice on this browser. The arrow beside it leaves the inbox and opens that conversation as its own page. Requires local `gws` credentials in `~/.config/gws` and `~/.config/gws-inhouse`, and the running WhatsAgent MCP endpoint. On this machine the existing `com.robert.whatsagent-headless` launch agent runs the backend independently of its UI. The plugin only attaches to that backend and never starts or restarts it; if discovery or the process is unavailable, it fails closed rather than risking a second WhatsApp connection. The plugin server reads private messages and exposes them through BB plugin RPC; only install on a trusted BB server and trusted clients.

Currently supports the latest 20 inbox threads per Gmail account, latest 50 WhatsApp chats, reading, Gmail archive/read/unread, local WhatsAgent mark-read, 1:1 WhatsApp replies, WhatsApp photos and stickers that load as they scroll into view, and video play tiles. In WhatsApp group chats, incoming message bodies are prefixed with the sender's name so each bubble says who wrote it. Sending a WhatsApp reply creates a proposal, then BB asks you to confirm it in the thread on the left. An agent calling the same action cannot complete the send without that confirmation. Cancelling withdraws the proposal. WhatsApp mark-read does not send a read receipt. Gmail draft controls are previews only: sending is disabled until end-to-end verification.

**Not a complete inbox:** Gmail reply/compose, pagination, search, Gmail attachments, WhatsApp archive/unread, group replies, and WhatsApp audio/document playback are not implemented. While the panel is mounted and visible, it polls every 60 seconds without overlapping refreshes; WhatsAgent maintains its own connection. Sources load independently, with the first five Gmail threads shown before the full 20 arrive. Gmail list uses one API request per thread. Do not use this prototype as a replacement for Gmail or WhatsAgent.

The latest 20 Gmail thread titles and previews per account are stored in BB's plugin database and shown on reopening; these are sensitive, unencrypted local data accessible to trusted BB server users. Each successful full refresh replaces that account's cached entries; failed refreshes retain stale entries. `bb plugin rpc call unified-inbox clear_cache` clears only the plugin cache, not Gmail. Active refreshes can repopulate it. The cache is not incremental synchronization and does not provide pagination.

WhatsApp photos and stickers load on demand from WhatsAgent's loopback media endpoint when they scroll into view. Videos show a play tile and load on click. The plugin server reads the bytes with the existing local bearer token and returns a bounded media data URL; nothing is uploaded. Images are capped at 6 MB, videos at 30 MB, and audio and documents stay as text placeholders. Rendered images stay in a bounded in-memory cache, so reopening a thread does not fetch them again. The message list keeps its scroll position unless you are at the bottom, and follows the bottom while photos finish decoding.

Build: `npx tsc --noEmit && bb plugin build`. It is not installed automatically.

LinkedIn is not implemented. LinkedIn conversations, InMail, and invites are planned as a read-only source attached to a locally run LinkedIn MCP server; access options and their ToS/account risk are compared in [docs/research/linkedin/linkedin-inbox-options.md](./docs/research/linkedin/linkedin-inbox-options.md) and the plan is [docs/plans/2026-10-28-002-feat-linkedin-inbox-source-plan.md](./docs/plans/2026-10-28-002-feat-linkedin-inbox-source-plan.md).
